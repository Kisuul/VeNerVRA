# Ven 2 — Hostile release-gate audit of Ven 2.1.0.2

**Decision:** **NO-GO.** Ven 2.1.0.2 is **not** ready to be treated as a verified foundation for the 2.1.1 provenance-envelope milestone. Do not merge PR #6 or promote the version on the strength of conventional CI.

**Frozen target:** `Kisuul/VeNerVRA` [PR #6](https://github.com/Kisuul/VeNerVRA/pull/6), head `f476112b1389a66a7821fa30ddb2dc47622a3302`; target branch `fix/ven-2.1.0.2-continuity-hardening-2026-11-09`, based on the 2.1.0.1 feature branch. This audit did **not** change the target.
**Independent execution environment:** [GitHub Actions run 42713478828](https://github.com/Kisuul/VeNerVRA/actions/runs/42713478828), 67 passing tests, global validator PASS, whitespace PASS.
**Reproducers:** [tests/test_journal_hostile_ven2_2102.py](../../tests/test_journal_hostile_ven2_2102.py), audit-only branch `audit/ven-2.1.0.2-hostile-2026-11-09`.
**Test semantics:** Eight hostile tests were designed to PASS *when an undesirable behavior is reproduced*; one is a positive control. Green audit CI **does not mean the candidate passed hostile review**.
**Reviewer independence:** This is a separate adversarial research pass in the **same ChatGPT model/session**, using independent CI process execution. It is **not** a second-model or fresh-context continuity trial.

## Baseline, methodology, and trust

Source reviewed at the frozen target: `tools/journal.py`, `tools/validate_seed.py`, `tests/test_journal_regression_2102.py`, `ven/JOURNAL_PROTOCOL.md`, `docs/ven-2.1/RELEASE_2.1.0.2.md`, and `docs/ven-2.1/FRESH_CONTEXT_GATE.md`.

The auditor wrote synthetic test fixtures and disposable working copies. No credentials, personal data, production agents, or external effects were used. Hostile tests include a **fake, inert token-shaped string** to test the optional preflight. A controlled monkeypatch models concurrent file replacement; it is not evidence that such a race occurred in production.

The foundational invariants are:
1. An index records an **actual** link to a real, inspected record; escaped or hidden syntax cannot register material.
2. Structural validation must reveal every intentionally durable research record, not silently exclude plausible storage locations.
3. A record returned as validated must be the **same byte snapshot** whose digest is shown to the consumer.
4. Recovery must preserve substantive decisions and attribution without confusing metadata with authority.
5. A fresh-model continuity claim requires **a separate model-context experiment**, not a Python subprocess.

## Findings by root cause

### V2.2-F01 — HIGH / CONFIRMED — Backslash-escaped links still authorize index registration

**Source:** `tools/validate_seed.py:37,145-166`, `tools/journal.py:128-133,154-175`.
**Probes:** `test_h01_escaped_markdown_link_counts_as_registration`; `test_h08_escaped_root_link_counts_as_investigation_registration`.

In an investigation's `INDEX.md`, `\\[Example](journal-one.md)` is **literal bracketed text**, not a Markdown link. The current regex nonetheless recognizes the bracket sequence and `index_links_to` returns true. The real journal checker accepts the file and `resume` returns it. A matching fake link in `research/INDEX.md` can also make an investigation appear registered. The bracket escaping is defined by [CommonMark's backslash-escape rules](https://spec.commonmark.org/current/#backslash-escapes).

**Significance:** This reintroduces the substance of 2.1.0's F-02 despite the 2.1.0.1/2.1.0.2 link-fixing milestones. A contributor able to modify index files can register material without a genuine navigable index link. **No privilege escalation or tool execution was demonstrated.**

**Required fix:** Parse index links with a consistent, documented Markdown dialect that honors escaping, or reject escaped link candidates explicitly. Add **fail-on-bug** regressions at both local and root indexes and test ordinary valid links.

### V2.2-F02 — HIGH / CONFIRMED — Validated repository can silently omit durable-looking records

**Source:** `tools/validate_seed.py:202-213,276-288,291-337`; `tools/journal.py:153-175`.
**Probes:** `test_h02_root_level_orphan_record_is_invisible_to_validator`; `test_h03_nested_orphan_record_is_invisible_to_validator`.

Adding `research/journal-lost.md` without schema, or `research/ven-methodology/uncatalogued/journal-lost.md`, leaves whole-repository validation returning `[]` even though the new Markdown has no frontmatter or index coverage. Recovery never enumerates these files. The existing orphan detector inspects *direct* child folders of `research` for missing `INDEX.md`, but does not inspect root-level Markdown or nested unexplained research subfolders.

**Significance:** This is *silent omission*, not authentication compromise. For a continuity repository, undetected unindexed research content is a core reliability defect. A strict policy that forbids these paths must **reject them**, rather than silently pass CI.

**Required fix:** Enforce an explicit allowlist for root-level `research/` contents; recursively detect non-indexed Markdown in real investigations (or document and enforce a separate scratch path). Include invalid root/nested fixtures in CI.

### V2.2-F03 — MEDIUM / CONDITIONAL INTEGRITY RISK — Validation and returned digest use different file snapshots

**Source:** `tools/journal.py:169-176,197-216`, `tools/validate_seed.py:221-225`.
**Probe:** `test_h07_read_validate_race_accepts_unvalidated_snapshot`.

The reader takes `raw = actual.read_bytes()`, then calls `validate_record(actual, slug)`, which **reads the pathname again**. Journal checks independently reopen the same file. The audit monkeypatched the boundary to simulate another local process replacing the file between reads. The returned summary and SHA-256 identify the **earlier, invalid bytes**, while structural validation succeeds against the **later, valid bytes**.

**Significance:** This is a controlled **time-of-check/time-of-use proof** under a concurrent-writer assumption—not a production attack, and not a bypass of an immutable pinned checkout. It matters acutely before 2.1.1 signing work: an attestation must not bind a digest of content other than the validated bytes.

**Required fix:** Read each record once into an immutable byte buffer; parse, structurally validate, derive sections, and hash **that same buffer**. Optionally require a verified clean/pinned checkout and reject changes during recovery; test controlled interleavings.

### V2.2-F04 — MEDIUM / CONFIRMED — Placeholder-only active handoffs pass the substantive-content gate

**Source:** `tools/validate_seed.py:216-219,250-265`, `tools/journal.py:173-215`.
**Probe:** `test_h04_placeholder_handoff_is_accepted_as_substantive`.

An active handoff with `## Summary` set to `[Replace with summary]`, `## Evidence` set to `[Replace with observed evidence]`, and `## Next decisive check` set to `[State the next discriminating check.]` passes `validate_record` and is returned as an active recovery record. The nonempty check excludes only a small set of exact placeholder strings.

**Significance:** This doesn't prove the reader would misinterpret the placeholder as factual truth; it proves that the documented *substantive* gate is weaker than asserted. Other heuristics or human review might catch it, but the automatic acceptance path does not.

**Required fix:** Detect known placeholder patterns in active handoffs, require a concrete next-check field, and mark unready drafts honestly. Do not imply static string checks establish scientific usefulness.

### V2.2-F05 — MEDIUM / POLICY GAP — Public-by-label retrieval does not enforce the available suspicious-content preflight

**Source:** `tools/journal.py:87-103,141-235`.
**Probe:** `test_h05_public_misclassification_bypasses_suspicious_content_tripwire`.

A journal self-labeled `sensitivity: public`, containing a **fake** token-shaped string, passes the ordinary structural check and is returned through the default `resume` call. Invoking the **optional** `check_journal(..., public=True)` *does* flag the string. The global structural validator and default reader do not require that check.

**Significance:** **No real secret was used or disclosed**, and the protocol explicitly says sensitivity metadata and the preflight are *not* host authorization or privacy certification. This is not a claimed access-control bypass. It is an operational hygiene gap that permits accidental exposure if a caller trusts the `public` label without an actual review.

**Required fix:** Make intended public publication explicitly depend on privacy review; consider optional fail-closed public-preflight for default retrieval, and keep host-enforced authorization and sensitivity labels separate. Do not present a regex scan as a security guarantee.

### V2.2-F06 — LOW / CONFIRMED FALSE REJECTION — Inline-code HTML comment syntax breaks otherwise valid journal structure

**Source:** `tools/validate_seed.py:97-125`.
**Probe:** `test_h06_inline_code_comment_example_hides_valid_journal`.

The literal inline code `<!--` is not an HTML comment in Markdown, but `visible_markdown_lines` checks for the raw substring **before** stripping inline code. It enters comment mode and silently excludes following headings until a literal closing `-->` appears. A properly formed, otherwise valid journal is rejected.

**Significance:** This is a false-negative/availability issue, not content spoofing or code execution. It shows that the scanner has inconsistent treatment of inline code and comments.

**Required fix:** Tokenize inline code and comments in the correct order under the declared restricted grammar; test examples with literal `<!--` and `-->`.

### V2.2-F07 — HARD RELEASE GATE / NOT RUN — Genuine successor-model continuity is still unverified

The candidate's own [fresh-context test specification](../ven-2.1/FRESH_CONTEXT_GATE.md) is marked **NOT RUN**. No independent agent/model session with isolated context and withheld grading was executed in this audit, and previous Python-process read-back is not a substitute. This is an **unmet acceptance requirement**, not a fresh code vulnerability.

## Positive controls, exclusions, and interpretation

- **PASS:** A correctly linked, static journal is recovered with evidence, sensitivity label, byte digest, and an explicit `unsigned_repository_content` assurance label.
- **PASS:** The audit's inert embedded command did **not** execute. There is no observed arbitrary code execution from Markdown, tool-authority inheritance, signature forgery, or exposure of actual credentials.
- **PASS within their tested fixtures:** The earlier 2.1.0.2 mitigations reject raw HTML headings, missing journal sections, ISO week dates, entirely empty handoffs, and directly orphaned research folders. They are real but incomplete fixes.
- **NOT ESTABLISHED:** Continuous first-person identity, authenticated model weights, trusted signing keys, runtime privilege policy, independently reproducible research accuracy, privacy certification, or a model's ability to revise inherited mistakes.
- **Source/audit independence:** This is one assistant's adversarial pass run through external GitHub CI. It is not independent second-model review. Any future model-continuity claim requires explicit separate execution and records.

## Decision and release conditions

**NO-GO** for merging/promoting PR #6 and treating 2.1.0.2 as the accepted foundation for 2.1.1.

Before lifting the gate:
1. Fix escaped-link registration and orphan-record visibility (F01/F02).
2. Make byte snapshot, schema validation, journal extraction and digest agree under concurrent writes or a truly immutable read (F03).
3. Harden active handoff readiness and public-content process semantics (F04/F05); correct inline-comment parsing (F06).
4. Invert **all** audit fixtures into production tests that FAIL if these undesirable conditions recur; run on the final pinned commit and preserve negative findings.
5. Execute a **genuinely fresh-model** continuity test with withheld expected facts, independently assess its results, and record all actual model IDs, source digests and tool use (F07).

Pure design exploration of 2.1.1 may proceed as a separate untrusted research activity, but **do not couple a signing or authority system to this memory parser and declare it operationally trusted** until these gates are satisfied. A signature proves which bytes were signed by a trusted key—not that an unvalidated record is safe or correct.

**Disposition:** PR #6 stays draft; no merges, deployments, changes to the 2.0 contract, or Kestrel writes were made by this audit.
