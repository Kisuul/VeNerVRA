**Verdict: NO-GO.** Do not merge PR #5 as a completed 2.1.0.1 release, and do not advance to 2.1.1 on a claimed continuity foundation.

**Target:** [VeNerVRA PR #5](https://github.com/Kisuul/VeNerVRA/pull/5), frozen head \`f3634a51488ba69e856c2d6340609aedd11ccb8c\`.
**Baseline:** [PR #4](https://github.com/Kisuul/VeNerVRA/pull/4), head \`a0b1032e957c144eab8ab154d25292b5192be533\`.
**Audit isolation:** \`audit/ven-2.1.0.1-hostile-2026-11-09\`, based on target head; target branch and \`main\` were not modified.
**Reproducers:** [audit-only test suite](../../tests/test_journal_hostile_ven2.py).
**Observed execution:** [GitHub Actions run 42596296983](https://github.com/Kisuul/VeNerVRA/actions/runs/42596296983) — 55 tests passed, structural check passed, whitespace passed. Ten new audit tests ran: nine affirm reproduced deficiencies, one is a positive/negative control. **A passing hostile test means the undesirable target behavior occurred.** It is not a security sign-off.
**Reviewer independence:** Ven 2 is an adversarial review role within the current ChatGPT session, NOT an independently instantiated second model/runtime. CI is an independent Python process, not a fresh-model continuity trial.

## Scope and attack surface

Inspected \`tools/journal.py\`, \`tools/validate_seed.py\`, \`tests/test_journal_regression_2101.py\`, \`.github/workflows/validate.yml\`, \`ven/JOURNAL_PROTOCOL.md\`, and the 2.1.0.1 release specification on the frozen SHA. Probed only disposable repository copies and synthetic journal/index fixtures using GitHub-hosted CI. No external credentials, production services, or destructive actions were accessed.

Audit invariants:

1. Journal sections and registration links must represent real supported source structure, not hidden examples.
2. CI must reject records violating the journal protocol, rather than reporting a false-green structural gate.
3. Every returned resumable handoff must contain useful, appropriately labeled recovery information.
4. Reader behavior must be deterministic for metadata the validator accepts, and omissions must be visible.
5. A successful Python resume is not proof of a successor model's understanding or permissions.

## Findings (highest impact first)

### V2-F01 — HIGH / CONFIRMED — HTML raw blocks bypass the heading and index fixes

**Locations:** \`tools/validate_seed.py:97-166\`, \`tools/journal.py:105-135\`.
**Proof:** \`test_a4_raw_html_pre_can_forge_journal_headings\` and \`test_a5_raw_html_pre_can_forge_index_link\` PASS on the frozen target. A journal containing its only required headings inside an HTML \`pre\` block passes \`check_journal\`, and \`resume\` returns the forged summary. An \`INDEX.md\` containing only \`[link](journal.md)\` *inside a \`pre\` element* registers a record despite not containing an actual rendered Markdown link.

**Mechanism:** \`visible_markdown_lines\` excludes fenced code, indentation and HTML *comments*, but not raw HTML blocks. Under ordinary Markdown interpretation, markup inside \`pre\` is literal. This recreates the substance of 2.1.0 F-01/F-02 through an untested encoding, despite the intentional restricted dialect.

**Preconditions / counterpoint:** An actor must be able to introduce or modify an accepted journal/index file, and the scanner deliberately does not implement all CommonMark. This is not demonstrated code execution or tool privilege escalation. Nevertheless the protocol promises valid section structure and actual local index links, and does not reject raw HTML; the accepted adversarial cases contradict that guarantee.

**Fix and test:** Either explicitly forbid HTML blocks in indexed journals and indexes, or use a well-specified renderer-equivalent parser; fail closed on unsupported syntax. Regression tests must reject \`pre\`, \`script\`, \`style\`, and raw HTML link/pseudoheading samples while accepting legitimate Markdown.

### V2-F02 — HIGH / CONFIRMED — Repository CI accepts structurally invalid new journals

**Locations:** \`tools/validate_seed.py:168-204,222-262\`; \`tools/journal.py:105-135\`; \`.github/workflows/validate.yml\`.
**Proof:** \`test_a2_global_ci_validator_accepts_incomplete_new_journal\` copied the actual repository, added a new indexed journal with only Summary, Evidence and Revisit when, then observed \`validate_repo == []\` while \`check_journal\` reported missing Current alternatives and Decisions / reversals. The audit job still passed the standard CI stages.

**Mechanism:** Global validator enforces only three generic headers; journal-specific requirements are checked only when explicitly invoking \`journal.check_journal\` and for a couple of already-known unit fixtures. The GitHub Actions workflow invokes only the global structural validator and unit tests.

**Counterpoint:** The authoring protocol instructs writers to run a manual \`journal.py check\`. Such a review could catch the defect. This finding is about the **automatic release gate's false-green behavior**, not a claim that no manual control exists.

**Fix and test:** Move journal-specific schema and nonempty-content checks into the shared validator, or have CI systematically invoke the journal checker for every real journal. Add a fixture where an newly indexed journal is incomplete and assert the CI gate fails.

### V2-F03 — MEDIUM / CONFIRMED — Accepted ISO dates can break reader ordering

**Locations:** \`tools/validate_seed.py:182-193\`, \`tools/journal.py:188-191,204-219\`.
**Proof:** \`test_a7_valid_iso_week_date_passes_validator_but_breaks_recall\` sets \`updated: 2026-W46-1\` (a valid Python ISO week-date parse for 2026-11-09). Both structural and journal validation accept it, but \`resume\` raises \`ValueError: invalid literal for int\` while computing its sort key. \`test_a8_week_date_is_accepted_by_scaffold_despite_documented_format\` confirms the draft generator permits the same form.

**Fix and test:** Enforce a canonical \`YYYY-MM-DD\` full-match at both generation and record validation, or normalize dates to \`datetime.date\` objects before sorting. Test ISO week dates, compact ISO dates, and invalid dates.

### V2-F04 — MEDIUM / CONFIRMED — Empty active handoff is returned as a valid resume record

**Locations:** \`tools/validate_seed.py:194-198\`, \`tools/journal.py:160-187\`.
**Proof:** \`test_a3_handoff_without_content_is_returned_as_active\` creates a correctly indexed active handoff with three empty required headings. \`validate_record\` emits no errors, and \`resume\` returns status \`active\` with empty \`summary\` and \`revisit_when\`.

**Fix and test:** Validate required substantive fields and an explicit next decisive check for active handoffs (or mark incomplete handoffs as draft and make that visible). Detect placeholder-only content where applicable.

### V2-F05 — MEDIUM / CONFIRMED DATA LOSS AT API BOUNDARY — Evidence and reversals omitted from resume payload

**Location:** \`tools/journal.py:174-201\`.
**Proof:** \`test_a1_resume_omits_evidence_and_reversals\` places unique markers in Evidence, Current alternatives, and Decisions / reversals; the returned JSON contains none of them and does not include those keys.

**Counterpoint:** The original files remain intact, and the response contains a path and SHA-256 digest; a diligent agent with file access can retrieve the complete record. Therefore this is **not** permanent Git data loss. It is a fidelity and workflow risk if consumers mistake a compact summary for full rehydration.

**Fix and test:** Return explicit \`omitted_sections\` or \`requires_source_followup\` metadata, ensure the documented startup flow opens referenced full records before concluding on corrections, or include bounded evidence/reversal excerpts with provenance.

### V2-F06 — MEDIUM / CONFIRMED — Recall strips sensitivity and authorship labels

**Location:** \`tools/journal.py:175-201\`.
**Proof:** \`test_a6_resume_discards_privacy_and_authorship_labels\` creates an active restricted, unverified record with explicit author. The reader returns its summary but omits \`sensitivity\`, \`author\`, and \`confidence\`, although a separate \`--public-preflight\` would flag non-public sensitivity.

**Counterpoint:** The reader must already have filesystem access to read the input, and this test does not prove cross-permission disclosure. A heuristic public preflight is explicitly not a privacy guarantee. The risk is that a downstream summarizer loses the record's restriction and attribution labels.

**Fix and test:** Propagate these metadata labels in returned records; clarify or enforce a host-controlled permitted-sensitivity filter before retrieval into less-trusted contexts. Never imply that metadata alone authenticates the author.

### V2-F07 — MEDIUM / CONFIRMED — Orphan investigation directories silently escape validation

**Locations:** \`tools/validate_seed.py:207-219,240-262\`, \`tools/journal.py:140-148\`.
**Proof:** \`test_a9_orphan_research_directory_escapes_global_validation\` adds \`research/unindexed-methodology/journal-forgotten.md\` without an \`INDEX.md\`. Whole-repository validation returns no errors; \`resume\` refuses the investigation because its indexes are unavailable.

**Counterpoint:** This issue is inherited from the 2.0 validator rather than introduced solely by 2.1.0.1. Nonetheless, the user-facing continuity promise depends on locating every intentional durable research record. Treat non-indexed research directories as an explicit policy choice, not invisible data.

**Fix and test:** Enumerate direct \`research/\` directories and reject unindexed non-template, non-example directories that contain persisted files. Document any allowed scratch path separately and ensure it cannot be mistaken for durable memory.

### V2-F08 — RELEASE BLOCKER / NOT VERIFIED — No fresh-model continuity acceptance trial

The existing patch suite tests structural behavior and separate *Python processes*, not an independently started successor model with a held-out grading oracle. The release plan itself already acknowledges this. No complete functional-continuity acceptance evidence was observed. This is not a new source-level defect; it is an unmet release criterion.

## Negative results and limitations

- **PASS, narrow:** A correctly indexed ordinary journal is recovered; no shell command embedded as text was executed by the CLI in the control case.
- **PASS, narrow:** The 2.1.0.1 regression tests reject the originally tested fenced pseudosections, prose-only index mentions, duplicate IDs, and draft displacement. Those fixes are real for their tested inputs.
- **NOT DEMONSTRATED:** Runtime privilege escalation, leaked GitHub credentials, forged cryptographic attestation, actual privacy disclosure to an unauthorized party, or compromise of an agent model.
- **NOT EXECUTED:** A fresh model context, production deployment, cryptographic identity verification, or permission broker.
- **Scope caveat:** The hostile fixtures are new source code only on the isolated audit branch; PR #5 remains unchanged. Passing hostile tests attest to behavior only at the explicitly frozen SHA and test inputs.

## Gate and next decisive checks

**Decision: NO-GO / release approval withheld.** It would be premature to use this candidate as a verified foundation for 2.1.1.

Recommended correction order: fix HTML-block/section/index validation (V2-F01) and automate journal-specific validation (V2-F02), then enforce normalized dates (V2-F03), meaningful handoff requirements (V2-F04), and correct retrieval metadata (V2-F05/F06). Scan for orphan investigations (V2-F07). Re-run the **inverted** hostile regressions and require rejection of each previous failing fixture. Finally run and independently grade a real fresh-model resumption trial (V2-F08) before declaring 2.1.0.x ready.

**Do not merge audit-only tests that pass on bad behavior as product success tests.** Convert each to an assertion of corrected behavior on the remediation branch, preserving this evidence trail.
