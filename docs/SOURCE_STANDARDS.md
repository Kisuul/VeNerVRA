# Source standards by domain (candidate)

These are research heuristics, not an immutable ranking of people or institutions. Always examine relevance, independence, methodology, publication/record date, and direct access. A primary source can still be biased, mistaken, obsolete or insufficient for the claim.

| Domain | Prefer when available | Typical pitfalls |
| --- | --- | --- |
| Experimental physical sciences | Raw data, methods, replicable studies, instrumentation records, systematic reviews | Inadequate controls, nonindependent replications, unreported calibration or uncertainty |
| Mathematics and formal reasoning | Explicit assumptions, transparent derivation, checkable proof, independent symbolic/numeric checks | Unstated premises, invalid equivalence, numeric coincidence passed off as proof |
| Software engineering | Source at exact commit, official API specs, executable fixtures, reproducible benchmarks | Stale docs, mocked tests extrapolated to production, changed acceptance oracles |
| Medicine / public health | High-quality synthesized evidence, relevant trials, official health guidance, appropriate context | Generalizing population studies to an individual, study design limitations, outdated advice |
| Law and regulation | Controlling jurisdiction's statutes, regulations, binding decisions, official regulatory guidance | Wrong jurisdiction/date, informal summaries portrayed as binding legal authority |
| History / archival studies | Original contemporaneous records interpreted alongside scholarship and provenance | Forged/partial archives, translation ambiguity, retrospective bias |
| Economics / social science | Methods and dataset documentation, identifiable sampling, robust alternative models | Confounding, nonrepresentative samples, overclaiming causality |
| Contemporary events | Dated primary announcements, direct records, cross-checked contemporaneous reporting | Recirculated articles, future claims, timelines, source dependence |
| Personal testimony | Attributed, consent-aware account limited to speaker's experience | Treating testimony as independently verified general fact |
| Philosophy / ontology | Explicit definitions, logical validity, serious alternative arguments | Recasting metaphors as empirically demonstrated laws |

## Verification steps

1. Record the **precise claim** to be supported. Do not attach a generic link to an entire argument.
2. Seek the most direct source accessible; describe the actual source inspected, not an inaccessible original.
3. Note source age, author, methods, data ownership, revisions and jurisdiction/context where relevant.
4. Check whether apparently different references rely on the same underlying result/dataset.
5. Seek serious contradictory evidence and alternative explanations.
6. State what the evidence *does not* establish; use UNSOURCED if materially unsupported.
7. Verify citations before deliverable publication; source URL existence alone is not endorsement.

This table is a candidate procedure and has not been independently benchmarked as an effective research skill.
